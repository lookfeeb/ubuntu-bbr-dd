# BBR 一键安装与失败恢复

本文说明 v3.3.13 的 BBR 安装流程：使用 Linux 7.3.5 / Guard7 R2，保留既有 GCP 兼容修复。内核包核对散列后复用 v3.3.12 产物，原本地构建和独立 QEMU 安装、headers、回退及清理后启动验收记录保持原样；本次仅更新脚本，没有重新验收整机或修改观察用服务器。性能限制见 [Release 发布说明](https://github.com/lookfeeb/ubuntu-bbr-dd/releases/tag/v3.3.13)。

## 下载与安装顺序

未发布的本地包可通过 `BBR_DD_AUTO_UPDATE=0 BBR_PACKAGE_DIR=/绝对路径/资产目录 bash bbr.sh` 启动，再选择菜单 1 → 1。目录须包含当前目标的 image、headers 和 `SHA256SUMS`。安装先按清单校验并复制到私有缓存，再检查真实包元数据与驱动；不会改写来源目录，也不会缺包时回退到旧内核。APT 运行依赖仍可能需要联网。本地目录应来自自己已完成验收的构建产物。

1. 交互启动检查本项目最新正式 Release；脚本与清单来自同一 tag，SHA-256 和 Bash 语法检查通过才运行。内部依赖仍使用该版验证过的版本。
2. 预编译安装验证与脚本同 tag 的 Release 清单中 image / headers 的唯一有效散列、包名、版本、架构及活动设备驱动；同版本重试复用已验证缓存，部分下载支持有界续传。源码安装验证固定源码散列，再构建。
3. 安装前验证实际启动过的回退内核：镜像、initramfs、模块目录、软件包安装状态及唯一 GRUB 菜单项均须存在。重装当前同版本内核会覆盖其磁盘文件，因此必须使用另一套已记录的回退内核。
4. 备份本工具管理的配置与状态，固定回退内核为默认启动项，再执行 APT。这样 APT 的内核钩子提前更新 GRUB 时也会保留回退默认项。BBR 安装依赖及内核包均使用 `--no-remove`，需要删除包才能解决的依赖冲突会停止。
5. 验证新内核、驱动、非空 initramfs 和 GRUB，再复核回退内核，写入 Guard 配置、选择新默认项、准备健康检查服务。全部完成后提交安装事务；不会自动重启。

## 失败与重复执行

### 升级与同版本重装

菜单 1 安装的是该脚本固定的内核与 Guard 版本；启动时更新脚本，不表示内核包或算法一定有新版本。先通过菜单 2 查看运行内核，再与 [构建说明](recovery-build.md) 的内核、包版本及模块版本核对。同一内核标识重复安装属于重装，不会提升算法版本；仅刷新包版本而复用内核标识也会覆盖当前启动文件。

清理到单内核后，未来安装**不同内核标识**的新版本仍可将当前运行内核作为安装期间的回退；必须通过原有文件、驱动、GRUB 和软件包检查。重装**相同标识**则必须先准备另一套实际启动验证过的内核，不能删除回退检查来强行覆盖唯一内核。新版本要先完成独立来宾安装、启动、headers 与回退验收，再发布与脚本同 tag 的完整包和清单。

预编译资源达标不等于源码编译资源达标。源码路径检查实时可用内存约 1.5 GB、可用内存与 swap 合计约 4 GB、构建目录 30 GiB 空间；资源不足的云机应使用已经验收的预编译包。历史观察与升级评估已保存在 Release 开发资料包中。

### 安装中断与恢复

`/var/lib/bbr-kernel/install.XXXXXX/` 保存本次阶段、配置备份与退出码；`install-pending` 指向未完成事务。备份目录仅 root 可访问，保留供排查。

- APT、驱动、initramfs、GRUB 或服务配置失败，以及 INT / TERM / HUP 中断：尝试恢复 sysctl/modules 配置、网卡 initramfs hook、内核状态记录及回退 GRUB 配置；不执行软件包卸载。
- KILL 等无法运行退出处理的中断：保留事务标记，菜单重启和旧内核清理会停止。再次安装先恢复旧事务，再做安装预检；恢复完成且此前已经提交的事务不会被重复撤销。
- 恢复失败、备份缺失或记录路径异常：保留标记并停止，不把缺失备份当作“原文件不存在”。修复对应文件系统、权限或备份问题后再重试；不要直接删除标记绕过检查。
- 有待执行 DD 时：停止安装恢复，避免恢复旧 GRUB 覆盖 DD 引导。先在 DD 菜单取消待执行重装。
- 已安装成功、仍待启动验收时：沿用原有 `cleanup-pending` 保护，先完成新内核启动和检查，不叠加另一轮安装。

配置恢复不会回滚 APT/dpkg 数据库或已执行的软件包维护脚本。APT 被中断后可能仍要求修复包状态；具体错误以 APT 输出为准。普通退出及强制杀进程已做故障测试，断电写入持久性、磁盘损坏和完整系统回滚不在保证范围内。

## 启动后只保留当前 BBR

v3.3.12 在 Guard7 启动检查通过后，仅保留当前运行内核、模块和配套 headers；原回退内核、其他版本及会继续拉取它们的内核元包一起卸载。历史 v3.3.11 的保留回退策略不变，需使用新版脚本才会采用此行为。

菜单 4 不再要求存在 `cleanup-pending` 或 `rollback-release`，可重复执行，也适用于旧版已完成清理的机器。清理前核对运行版本与安装记录一致、Guard7 模块、image / headers 包、非空内核与 initramfs、模块目录、磁盘上的网卡驱动、GRUB 启动项和语法、SSH 与默认路由。先固定当前内核为默认项，再检查 APT 预演；禁止删除当前内核的配套包、连带删除其他应用或安装替代包。通用 `linux-tools-common`、`linux-libc-dev` 不属于待卸载内核。

卸载后更新启动链接与 GRUB，再次核对当前内核可用、其他内核包和文件已移除，最后关闭定时器并移除回退记录和任务标记。`cleanup-incomplete` 表示清理尚未收尾，菜单会阻止重启；修复错误后重试菜单 4，即使旧内核已经卸载也能继续。残留或手工安装的其他内核不会被盲目递归删除，而是报告未完成。清理无法恢复已卸载的包，清理后没有备用内核；如需重新安装同一内核版本，仍须先准备另一套可启动内核，避免覆盖唯一启动副本。

SSH 服务和默认路由检查只反映本机状态，外部 SSH/业务验收仍由实际连接确认。历史 GCP 公共 headers/tools 依赖修复仍用于识别当前 ABI 的配套包；其他 ABI 的配套包会随对应内核清理。

## 验证范围

`tests/test_bbr_install.py` 调用实际安装、GRUB 选择、配置恢复及事务函数，把所有文件路径重定向到临时目录，APT、systemd、initramfs 和 sysctl 均由模拟命令替代。覆盖成功提交、安装钩子中的默认项、各阶段失败、同版本重装、空镜像/initramfs、中断恢复、恢复失败、缺失备份、符号链接和 DD 冲突。

`tests/test_bbr_cleanup.py` 使用实际清理与 GRUB 配置函数，模拟 APT、驱动和服务，覆盖只保留当前版本、无旧任务记录、重复运行、健康检查失败、当前包保护、APT 假成功、卸载后 GRUB 失败重试、启动链接与未管理文件残留。

这能验证脚本控制流程，不等于实际包安装、真实 GRUB 启动或断电验收。实际包及历史性能验证见 [构建与验证](recovery-build.md)，2026-11-17 的云实例安装与回退结果见 [GCP 历史实测报告](https://github.com/lookfeeb/ubuntu-bbr-dd/blob/923da13f3b12515c01e62b937e9af63d257f26ab/docs/gcp-validation-20261117.md)。

安装函数将包目录转换为绝对路径后再调用 APT，避免将裸相对路径误当作软件包名称。
