# DD 验证链与失败处理

本文描述 v3.3.13 / DD 2.4.9 的重装流程，包括阶段记录、失败重试保护、磁盘身份和镜像快照检查。2.4.9 精简菜单，固定 root 密码登录与 SSH 22，并修改宿主端引擎适配补丁，通过独立文件描述符回传实际密码，供重启前显示。上游引擎提交不变；本次通过脚本回归验证，没有重新做整机 DD 验收。操作、平台条件及实测范围见 [README](../README.md)。

## 输入与信任链

1. 下载固定提交的 `bin456789/reinstall` tar.gz，验证内置 SHA-256 后只提取允许的普通辅助文件。Python 补丁逐一检查锚点，结构漂移即停止。
2. 加固脚本和辅助资源清单封入 initramfs，Alpine 启动后再次校验；资源包装器只访问封装文件，阶段自更新和切换系统入口被封闭。
3. 每次准备读取官方 `noble/release/` 或 `resolute/release/` 页面的当前发布构建号，再从对应 `release-YYYYMMDD[.N]/` 日期目录获取 `SHA256SUMS`、签名及镜像 HEAD。验证官方签名后精确匹配镜像条目；不按目录排序猜测最新构建。
4. 把日期 URL、构建号、大小和已认证清单封入资源包。重启后复用本次快照，再验签、下载并核对完整镜像散列；下次准备才重新查询最新构建。准备时日期资源缺失、重定向到其他地址、构建号异常或条目缺失/重复均停止，不退回动态 `release/`。

Ubuntu 公钥来自 `ubuntu-keyring` 中的 cloud image 密钥：

```text
UEC Image Automatic Signing Key <cdimage@ubuntu.com>
D2EB44626FDDC30B513D5BB71A5D6C4C7DB87C81
```

仓库公钥 SHA-256 为 `8d2fa6679588fe177ce4a2d76ee56a479e18307abd4d0afc115e4f55dc288767`。不从 keyserver 临时导入密钥；轮换必须核实官方信任锚。

准备和镜像下载限制为 HTTPS 及 HTTPS 重定向。initramfs 携带主机 CA，并以准备时刻作为时钟下限；上游无证书探测仅判断连通性，其响应不用于认证脚本或镜像。Alpine 启动资源依赖 HTTPS，动态 APK/APT 依赖各自签名，并非全部资源的固定哈希快照。

日期目录不能保证永久保留；重启后若快照已删除，下载仍会失败。固定 URL 避免正常发布切换引起的漂移，最终真实性仍由官方签名和完整散列保证，不提供磁盘模式写盘后的回滚。

## 目标磁盘身份

准备阶段记录分区表 ID（PTUUID）、容量，以及设备提供的 SERIAL / WWN，随资源包校验清单一起封装。`dd_disk.sh` 同时用于主机和安装环境，只有一个候选整盘匹配 PTUUID 才允许继续；即使克隆盘有不同序列号，也拒绝在重复 ID 间自行选择。

安装环境忽略旧 `/configs/xda` 选择缓存，重新扫描并核对引导参数、身份记录及容量。设备名可以变化，但已记录的 SERIAL / WWN 必须一致；丢失、读取失败或身份记录不完整均停止。预检和真正进入分区命令前各复核一次，RAM 下载期间或磁盘模式预检后出现克隆盘也会被拒绝，失败发生在写盘边界记录之前。

DD 2.4.6 修正了 Alpine 3.24 的两个兼容问题：`blockdev` 由 `util-linux-misc` 包提供；Alpine 的 `lsblk` 未链接 libudev，SERIAL / WWN 为空时使用 eudev 的 `scsi_id` 直接查询同一设备。非空的 `lsblk` 值不会被覆盖，记录值仍须严格匹配，重复属性也会拒绝。GCP 实机已验证能读取与原系统一致的磁盘序列号。

没有 SERIAL / WWN 的平台仅能验证唯一 PTUUID 和容量：原盘被另一块具有相同 ID、容量的磁盘完全替换时无法识别。检查也不构成磁盘热拔插的原子锁；安装期间不要更换或热插拔目标磁盘。

## 两种写盘边界

缓存模式在准备阶段确定并封入资源包，安装环境不静默切换。

| 阶段 | RAM 模式 | 磁盘模式 |
| --- | --- | --- |
| 分区前 | 复核唯一目标身份、MAC/驱动、路由；完整验证镜像、系统、计划内 Ubuntu 包及驱动 | 复核唯一目标身份、网络、签名清单、HTTPS 镜像端点和容量 |
| 缓存 | 独立 tmpfs；原系统总内存至少镜像大小加 2.25 GiB，安装环境可用内存至少镜像大小加 2 GiB | 分区后建立至少 6 GiB 的磁盘缓存和 2 GiB swap；系统盘至少 16 GiB |
| 开始写盘 | 镜像和计划内 Ubuntu 包的下载、验证全部通过后 | 完整镜像下载前，先清除原分区并建立新布局 |
| 失败影响 | 下载或预检失败不触发分区；清盘后的失败仍无法还原原系统 | 分区后下载或校验失败也无法还原原系统 |

两种模式都校验 QCOW2 结构并拒绝外部 backing/data file，检查 Ubuntu 版本、镜像容量、模块、计划包和真实所需驱动。预下载使用镜像内 APT 签名源，不执行包安装脚本；缓存计划、包和索引另有散列清单。复制系统和包缓存后再核验，后续 Ubuntu APT 操作使用 `--no-download`，不临时刷新索引或切换来源。

磁盘缓存大小为 `max(6 GiB, 镜像大小 + 4 GiB)`，此外至少保留 8 GiB；分区入口只允许执行一次。Ubuntu 包解压限制单线程，initramfs 使用 gzip。安装成功后清理镜像和包缓存，保留缓存分区及活动 swap，按 UUID 挂载到 `/var/lib/ubuntu-dd/scratch`。

512 MiB 是支持目标，允许内核预留后的 `MemTotal` 降至 448 MiB，不是整机实测或业务容量保证。Alpine APK 尚未全部离线化；复制、包安装脚本、引导和网络配置仍可能在写盘后失败。

## 阶段、锁与重试

当前运行时在 `/run/ubuntu-dd-install` 保存阶段、目标盘和退出码；第一次分区命令之前记录写盘边界。安装锁覆盖状态检查和退出记录，避免相邻尝试互相覆盖证据。

- 写盘前失败：可以重新执行完整预检；新尝试清除旧退出码，成功退出记录为 0。
- 同次启动写盘后失败：拒绝再次运行 `trans.sh`，防止重复清盘。该记录不能跳过验签，也不提供断电续装。
- INT / TERM / HUP：记录状态并按信号退出。强制杀死或断电无法运行退出处理，残留锁必须先人工核查。
- 失败后：保留安装环境，检查 `/reinstall.log` 与阶段记录，不要直接重启未完成目标。仅当磁盘缓存仍正确挂载时，额外写入 `/installer/dd-failure/`，不会为记录错误而挂载磁盘或卸载 swap。

菜单取消仅适用于原系统尚未重启进入安装环境时，不能撤销已经执行的写盘操作。

## 重启前登录信息

DD 菜单固定 root 密码登录、SSH 22，版本选择后使用自动平台与缓存策略。适配后的固定引擎在准备结束时通过父进程提供的私有文件描述符回传实际密码，包括用户输入与随机生成两种情况；密码不通过命令行参数传递，也不加入资源包或 initramfs。

原系统将密码保存在 `/var/lib/ubuntu-dd/login-password`，目录 `700`、文件 `600`。只有引擎成功退出且记录校验通过后才创建 `reinstall-ready`。重启确认前校验准备状态、普通文件、所属用户、权限与内容，用户名与密码分别着色显示；记录缺失、旧准备记录没有凭据或准备失败时，要求取消重装并重新准备。密码作为文本读取，不作为 Shell 代码加载。取消引导成功后删除密码与准备记录；取消失败则保留供排查。重装清盘会移除原系统记录。

## 目标系统检查

已识别平台选择对应的 `gcp` / `aws` / `oracle` 内核；generic 镜像不保证自带全部云驱动。复制前必须在已认证包内找到实际网卡和存储驱动，安装后再次检查模块、完整 initramfs、GRUB、`netplan generate` 与 `sshd -t/-T`。

cloud-init 仅识别实例，数据源限定 GCE / Ec2 / Oracle；禁用其网络生成和 user-data，模块只保留 seed_random，避免覆盖安装器配置的网络与登录方式。云代理和网页 SSH 集成不自动恢复。

首次启动的网卡名称修复服务使用早期启动依赖，在文件系统可写、udev 完成后运行，不等待 D-Bus，避免与 `cloud-init-local` 形成排序循环。GCE 元数据访问使用固定链路本地地址 `169.254.169.254`，避免早期 DNS 尚未就绪导致识别告警；该设置仅用于 GCP。

上述静态检查不能替代启动验收。新系统启动后必须从外部检查 SSH、HTTPS 和业务，并再次重启；本轮已验证范围见 [README](../README.md#平台条件与实测范围)。
